## ИМЯ:
 `bash — GNU Bourne-Again SHell`
## СИНТАКСИС :
`**bash** [параметры] [строка_команды | файл]`
## АВТОРСКИЕ ПРАВА
   Bash — это программа, защищённая авторским правом (C) 1989–2025
   организацией Free Software Foundation, Inc.
## ОПИСАНИЕ
   **Bash** — это интерпретатор командного языка, который выполняет
   команды, считанные из стандартного ввода, из строки или из файла.
   Это переработанная и расширенная версия оболочки Bourne, исторического
   интерпретатора командного языка Unix. **Bash** также включает полезные
   возможности из оболочек _Korn_ и _C_ (**ksh** и **csh**).

   POSIX — это название семейства стандартов вычислений, основанных на
   Unix. **Bash** предназначен для совместимой реализации части
   «Оболочка и утилиты» спецификации IEEE POSIX (стандарт IEEE 1003.1).
   **Режим POSIX** в bash (далее именуемый _режимом posix_) изменяет
   поведение оболочки там, где её работа по умолчанию отличается от
   стандарта, чтобы строго соответствовать стандарту.
   См. ниже **СМОТРИ ТАКЖЕ** для ссылки на документ, который подробно
   описывает, как режим posix влияет на поведение **bash**. **Bash** может
   быть настроен на соответствие POSIX по умолчанию.
## ПАРАМЕТРЫ
   Все однобуквенные параметры оболочки, документированные в
   описании встроенной команды **set**, включая **-o**, могут использоваться
   в качестве параметров при запуске оболочки. Кроме того, **bash**
   интерпретирует следующие параметры при запуске:

   **-c**     Если указан параметр **-c**, то команды считываются из
          первого непараметрического аргумента _строка_команды_. Если
          после _строки_команды_ есть аргументы, первый аргумент
          присваивается переменной **$0**, а оставшиеся аргументы
          присваиваются позиционным параметрам. Присваивание **$0**
          устанавливает имя оболочки, которое используется в
          предупреждающих и ошибках.

   **-i**     Если указан параметр **-i**, оболочка становится
          _интерактивной_.

   **-l**     Заставляет **bash** вести себя так, как если бы он был
          запущен как регистрационная оболочка (см. ниже **ЗАПУСК**).

   **-r**     Если указан параметр **-r**, оболочка становится
          _ограниченной_ (см. ниже **ОГРАНИЧЕННАЯ ОБОЛОЧКА**).

   **-s**     Если указан параметр **-s** или если после обработки
          параметров не осталось аргументов, оболочка читает команды
          из стандартного ввода. Этот параметр позволяет устанавливать
          позиционные параметры при запуске интерактивной оболочки
          или при чтении ввода через конвейер.

   **-D**     Выводит список всех строк в двойных кавычках, которым
          предшествует **$**, в стандартный вывод. Это строки, которые
          подлежат переводу, когда текущая локаль не **C** или **POSIX**.
          Это подразумевает параметр **-n**; никакие команды не будут
          выполнены.

   **[-+]O [**_параметр_shopt_**]**
          _параметр_shopt_ — это один из параметров оболочки,
          принимаемый встроенной командой **shopt** (см. ниже
          **ВСТРОЕННЫЕ КОМАНДЫ ОБОЛОЧКИ**). Если _параметр_shopt_
          указан, **-O** устанавливает значение этого параметра;
          **+O** снимает его. Если _параметр_shopt_ не указан,
          **bash** выводит имена и значения параметров оболочки,
          принимаемых **shopt**, в стандартный вывод. Если параметр
          запуска — **+O**, вывод отображается в формате, который
          может быть повторно использован как входные данные.

   **--**     **--** сигнализирует об окончании параметров и отключает
          дальнейшую обработку параметров. Любые аргументы после
          **--** рассматриваются как имя файла скрипта оболочки
          (см. ниже) и аргументы, передаваемые этому скрипту.
          Аргумент **-** эквивалентен **--**.

   **Bash** также интерпретирует ряд многобуквенных параметров. Эти
   параметры должны появиться в командной строке перед однобуквенными
   параметрами, чтобы быть распознанными.

   **--debugger**
          Обеспечивает выполнение профиля отладчика перед запуском
          оболочки. Включает расширенный режим отладки (см. описание
          параметра **extdebug** для встроенной команды **shopt** ниже).

   **--dump-po-strings**
          Эквивалентно **-D**, но вывод осуществляется в формате
          файла GNU _gettext_ «po» (portable object).

   **--dump-strings**
          Эквивалентно **-D**.

   **--help** Отображает справочное сообщение в стандартном выводе
          и завершается успешно.

   **--init-file** _файл_
   **--rcfile** _файл_
          Выполняет команды из _файла_ вместо стандартного персонального
          файла инициализации _~/.bashrc_, если оболочка интерактивна
          (см. ниже **ЗАПУСК**).

   **--login**
          Эквивалентно **-l**.

   **--noediting**
          Не использовать библиотеку GNU **readline** для чтения строк
          команд, когда оболочка интерактивна.

   **--noprofile**
          Не читать ни системный стартовый файл _/etc/profile_, ни
          какие-либо персональные файлы инициализации _~/.bash_profile_,
          _~/.bash_login_ или _~/.profile_. По умолчанию **bash** читает
          эти файлы, когда запускается как регистрационная оболочка
          (см. ниже **ЗАПУСК**).

   **--norc** Не читать и не выполнять персональный файл инициализации
          _~/.bashrc_, если оболочка интерактивна. Этот параметр
          включён по умолчанию, если оболочка запускается как **sh**.

   **--posix**
          Включает режим posix; изменяет поведение **bash** там, где
          работа по умолчанию отличается от стандарта POSIX, чтобы
          соответствовать стандарту.

   **--restricted**
          Оболочка становится ограниченной (см. ниже
          **ОГРАНИЧЕННАЯ ОБОЛОЧКА**).

   **--verbose**
          Эквивалентно **-v**.

   **--version**
          Показывает информацию о версии этого экземпляра **bash** в
          стандартном выводе и завершается успешно.
 ## АРГУМЕНТЫ 
   Если после обработки параметров остались аргументы, и не были
   указаны параметры **-c** или **-s**, то первый аргумент рассматривается
   как имя файла, содержащего команды оболочки (_скрипт оболочки_).
   Когда **bash** запускается таким образом, **$0** устанавливается в
   имя файла, а позиционные параметры устанавливаются в оставшиеся
   аргументы. **Bash** читает и выполняет команды из этого файла, затем
   завершается. Статус завершения **bash** — это статус завершения
   последней выполненной команды в скрипте. Если не выполнено ни одной
   команды, статус завершения равен 0. **Bash** сначала пытается открыть
   файл в текущем каталоге, и, если файл не найден, ищет скрипт в
   каталогах, указанных в **PATH**. 
   ## ЗАПУСК
   _Регистрационная оболочка_ — это оболочка, первый символ нулевого
   аргумента которой является **-**, или оболочка, запущенная с параметром
   **--login**.

   _Интерактивная оболочка_ — это оболочка, запущенная без
   непараметрических аргументов (если не указан **-s**) и без параметра
   **-c**, и чьи стандартный ввод и стандартный вывод ошибок оба
   подключены к терминалам (как определено [isatty(3)](https://man7.org/linux/man-pages/man3/isatty.3.html)), или оболочка,
   запущенная с параметром **-i**. **Bash** устанавливает **PS1**, а
   **$-** включает **i**, если оболочка интерактивна, поэтому скрипт
   оболочки или стартовый файл могут проверить это состояние.

   Следующие абзацы описывают, как **bash** выполняет свои стартовые
   файлы. Если какой-либо из файлов существует, но не может быть
   прочитан, **bash** сообщает об ошибке. Тильды в именах файлов
   раскрываются, как описано ниже в разделе **Раскрытие тильды** в
   разделе **РАСКРЫТИЕ**.

   Когда **bash** запускается как интерактивная регистрационная
   оболочка или как неинтерактивная оболочка с параметром **--login**,
   он сначала читает и выполняет команды из файла _/etc/profile_,
   если этот файл существует. После чтения этого файла он ищет
   _~/.bash_profile_, _~/.bash_login_ и _~/.profile_, в указанном порядке,
   и читает и выполняет команды из первого существующего и читаемого
   файла. Параметр **--noprofile** может использоваться при запуске
   оболочки, чтобы подавить это поведение.

   Когда интерактивная регистрационная оболочка завершается или
   неинтерактивная регистрационная оболочка выполняет встроенную
   команду **exit**, **bash** читает и выполняет команды из файла
   _~/.bash_logout_, если он существует.

   Когда запускается интерактивная оболочка, не являющаяся
   регистрационной, **bash** читает и выполняет команды из _~/.bashrc_,
   если этот файл существует. Параметр **--norc** подавляет это поведение.
   Параметр **--rcfile** _файл_ заставляет **bash** использовать _файл_
   вместо _~/.bashrc_.

   Когда **bash** запускается неинтерактивно, например, для запуска
   скрипта оболочки, он ищет переменную **BASH_ENV** в окружении,
   раскрывает её значение, если оно там есть, и использует раскрытое
   значение как имя файла для чтения и выполнения. **Bash** ведёт себя,
   как если бы была выполнена следующая команда:

          if [ -n "$BASH_ENV" ]; then . "$BASH_ENV"; fi

   но не использует значение переменной **PATH** для поиска имени файла.

   Если **bash** запускается с именем **sh**, он пытается максимально
   близко имитировать поведение при запуске исторических версий **sh**,
   одновременно соответствуя стандарту POSIX. При запуске в качестве
   интерактивной регистрационной оболочки или неинтерактивной оболочки
   с параметром **--login** он сначала пытается читать и выполнять
   команды из _/etc/profile_ и _~/.profile_, в указанном порядке.
   Параметр **--noprofile** подавляет это поведение. При запуске в
   качестве интерактивной оболочки с именем **sh**, **bash** ищет
   переменную **ENV**, раскрывает её значение, если оно определено, и
   использует раскрытое значение как имя файла для чтения и выполнения.
   Поскольку оболочка, запущенная как **sh**, не пытается читать и
   выполнять команды из каких-либо других стартовых файлов, параметр
   **--rcfile** не имеет эффекта. Неинтерактивная оболочка, запущенная
   с именем **sh**, не пытается читать какие-либо другие стартовые файлы.

   При запуске как **sh**, **bash** входит в режим posix после чтения
   стартовых файлов.

   Когда **bash** запускается в режиме posix, как с параметром
   командной строки **--posix**, он следует стандарту POSIX для
   стартовых файлов. В этом режиме интерактивные оболочки раскрывают
   переменную **ENV** и читают и выполняют команды из файла, имя
   которого является раскрытым значением. Никакие другие стартовые
   файлы не читаются.

   **Bash** пытается определить, когда он запущен со стандартным
   вводом, подключённым к сетевому соединению, как при выполнении
   историческим и редко встречающимся демоном удалённой оболочки,
   обычно _rshd_, или демоном безопасной оболочки _sshd_. Если **bash**
   определяет, что он запущен неинтерактивно таким образом, он читает
   и выполняет команды из _~/.bashrc_, если этот файл существует и
   читаем. **Bash** не читает этот файл, если запущен как **sh**.
   Параметр **--norc** подавляет это поведение, а параметр **--rcfile**
   заставляет **bash** использовать другой файл вместо _~/.bashrc_, но
   ни _rshd_, ни _sshd_ обычно не запускают оболочку с этими параметрами
   или не позволяют их указать.

   Если оболочка запущена с эффективным идентификатором пользователя
   (группы), не равным реальному идентификатору пользователя (группы),
   и параметр **-p** не указан, то стартовые файлы не читаются,
   функции оболочки не наследуются из окружения, переменные
   **SHELLOPTS**, **BASHOPTS**, **CDPATH** и **GLOBIGNORE**, если они
   присутствуют в окружении, игнорируются, и эффективный идентификатор
   пользователя устанавливается в реальный идентификатор пользователя.
   Если при запуске указан параметр **-p**, поведение при запуске
   такое же, но эффективный идентификатор пользователя не сбрасывается.
   ## ОПРЕДЕЛЕНИЯ
   Следующие определения используются во всём остальном документе.
   **blank**  Пробел или табуляция.
   **whitespace**
          Символ, принадлежащий классу символов **space** в текущей
          локали, или для которого `isspace(3)`возвращает истину.
   **word**   Последовательность символов, рассматриваемая оболочкой
          как единое целое. Также известна как **token**.
   **name**   _Слово_, состоящее только из буквенно-цифровых символов и
          подчёркиваний и начинающееся с буквы или подчёркивания.
          Также называется **identifier**.
   **metacharacter**
          Символ, который, когда не процитирован, разделяет слова.
          Один из следующих:
          **|  & ; ( ) < > space tab newline**
   **control operator**
          _Токен_, который выполняет управляющую функцию. Это один
          из следующих символов:
          **|| & && ; ;; ;& ;;& ( ) | |& <newline>**
## ЗАРЕЗЕРВИРОВАННЫЕ СЛОВА   
   _Зарезервированные слова_ — это слова, которые имеют особое значение
   для оболочки. Следующие слова распознаются как зарезервированные,
   когда они не процитированы и либо являются первым словом команды
   (см. ниже **ГРАММАТИКА ОБОЛОЧКИ**), либо третьим словом команды
   **case** или **select** (только **in** допустимо), либо третьим словом
   команды **for** (только **in** и **do** допустимы):

   **! case  coproc  do done elif else esac fi for function if in**
   **select then until while { } time [[ ]]**
## ГРАММАТИКА ОБОЛОЧКИ
      В этом разделе описывается синтаксис различных форм команд оболочки.
### Простые команды.
Простая команда — это последовательность необязательных присваиваний
переменных, за которыми следуют слова и перенаправления, разделённые
blank, и завершающиеся оператором управления. Первое слово
указывает команду для выполнения и передаётся как аргумент ноль.
Оставшиеся слова передаются как аргументы вызванной команде.

      Возвращаемым значением _простой команды_ является её статус завершения или 128+_n_, если команда завершена сигналом _n_.
### Конвейеры
Конвейер — это последовательность одной или более команд,
разделённых одним из операторов управления | или |&. Формат
конвейера:
          [**time** [**-p**]] [ ! ] _command1_ [ [**|**⎪**|&**] _command2_ ... ]

   Стандартный вывод _command1_ соединяется через конвейер со
   стандартным вводом _command2_. Это соединение выполняется перед
   любыми перенаправлениями, указанными _command1_ (см. ниже
   **ПЕРЕНАПРАВЛЕНИЕ**). Если **|&** является оператором конвейера,
   стандартный вывод ошибок _command1_ в дополнение к стандартному
   выводу соединяется со стандартным вводом _command2_ через конвейер;
   это сокращение для **2>&1 |**. Это неявное перенаправление стандартного
   вывода ошибок в стандартный вывод выполняется после любых
   перенаправлений, указанных _command1_.

   Статус конвейера — это статус завершения последней команды, если
   только не включена опция **pipefail**. Если **pipefail** включена,
   статус конвейера — это значение последней (самой правой) команды,
   завершившейся с ненулевым статусом, или ноль, если все команды
   завершились успешно. Если зарезервированное слово **!** предшествует
   конвейеру, статус завершения этого конвейера является логическим
   отрицанием статуса завершения, как описано выше. Если конвейер
   выполняется синхронно, оболочка ждёт завершения всех команд в
   конвейере перед возвратом значения.

   Если зарезервированное слово **time** предшествует конвейеру,
   оболочка сообщает затраченное время, а также пользовательское и
   системное время, потреблённое его выполнением, когда конвейер
   завершается. Параметр **-p** изменяет формат вывода на указанный
   POSIX. Когда оболочка находится в режиме posix, она не распознаёт
   **time** как зарезервированное слово, если следующий токен начинается
   с «-». Значение переменной **TIMEFORMAT** является строкой формата,
   которая определяет, как должна отображаться информация о времени;
   см. описание **TIMEFORMAT** ниже в разделе **Переменные оболочки**.

   Когда оболочка находится в режиме posix, **time** может появляться
   само по себе как единственное слово в простой команде. В этом случае
   оболочка отображает общее пользовательское и системное время,
   потреблённое оболочкой и её дочерними процессами. Переменная
   **TIMEFORMAT** задаёт формат информации о времени.

   Каждая команда в многокомандном конвейере, где создаются конвейеры,
   выполняется в _подоболочке_, которая является отдельным процессом.
   См. **СРЕДА ВЫПОЛНЕНИЯ КОМАНД** для описания подоболочек и среды
   подоболочки. Если опция **lastpipe** включена с помощью встроенной
   команды **shopt** (см. описание **shopt** ниже), и управление заданиями
   не активно, последний элемент конвейера может быть запущен процессом
   оболочки.
### Списки
      Список — это последовательность одного или более конвейеров,
      разделённых одним из операторов ;, &, && или ||, и
      необязательно завершающаяся одним из ;, & или <newline>.
   Из этих операторов списка **&&** и **||** имеют одинаковый приоритет,
   за которым следуют **;** и **&**, которые также имеют одинаковый приоритет.

   Последовательность из одного или более символов новой строки может
   появиться в _списке_ вместо точки с запятой для разделения команд.

   Если команда завершается оператором управления **&**, оболочка
   выполняет команду в _фоне_ в подоболочке. Оболочка не ждёт
   завершения команды, и возвращаемый статус равен 0. Такие команды
   называются _асинхронными_. Команды, разделённые **;**, выполняются
   последовательно; оболочка ждёт завершения каждой команды по очереди.
   Возвращаемый статус — это статус завершения последней выполненной
   команды.

   Списки И и ИЛИ — это последовательности одного или более конвейеров,
   разделённых операторами управления **&&** и **||** соответственно.
   Списки И и ИЛИ выполняются с левой ассоциативностью. Список И имеет
   вид:

          _command1_ **&&** _command2_

   _command2_ выполняется тогда и только тогда, когда _command1_
   возвращает статус завершения ноль (успех).

   Список ИЛИ имеет вид:

          _command1_ **||** _command2_

   _command2_ выполняется тогда и только тогда, когда _command1_
   возвращает ненулевой статус завершения. Возвращаемым статусом
   списков И и ИЛИ является статус завершения последней выполненной
   команды в списке.
   ### Составные команды
      Составная команда — это одна из следующих. В большинстве случаев
      список в описании команды может быть отделён от остальной части
      команды одним или более символами новой строки и может следовать
      за новой строкой вместо точки с запятой.
   (_list_) _list_ выполняется в подоболочке (см. **СРЕДА ВЫПОЛНЕНИЯ**
          **КОМАНД** ниже для описания среды подоболочки). Присваивания
          переменных и встроенные команды, которые влияют на окружение
          оболочки, не остаются в силе после завершения команды.
          Возвращаемым статусом является статус завершения _list_.

   { _list_; }
          _list_ выполняется в текущем окружении оболочки. _list_
          должен завершаться символом новой строки или точкой с запятой.
          Это известно как _групповая команда_. Возвращаемым статусом
          является статус завершения _list_.

          Обратите внимание, что в отличие от метасимволов **(** и **)**,
          **{** и **}** являются _зарезервированными словами_ и должны
          появляться там, где разрешено распознавание зарезервированного
          слова. Поскольку они не вызывают разрыва слова, они должны
          быть отделены от _list_ пробелом или другим метасимволом
          оболочки.

   ((_expression_))
          Арифметическое _выражение_ вычисляется согласно правилам,
          описанным ниже в разделе **АРИФМЕТИЧЕСКИЕ ВЫЧИСЛЕНИЯ**. Если
          значение выражения ненулевое, возвращаемый статус равен 0;
          в противном случае возвращаемый статус равен 1. _Выражение_
          подвергается тем же раскрытиям, как если бы оно было в
          двойных кавычках, но неэкранированные двойные кавычки в
          _expression_ не обрабатываются особым образом и удаляются.
          Поскольку это может потенциально привести к пустым строкам,
          эта команда рассматривает их как выражения, которые
          вычисляются в 0.

   **[[** _expression_ **]]**
          Вычисляет условное выражение _expression_ и возвращает
          статус ноль (истина) или ненулевой (ложь). Выражения
          состоят из примитивов, описанных ниже в разделе
          **УСЛОВНЫЕ ВЫРАЖЕНИЯ**. Слова между **[[** и **]]** не
          подвергаются разбиению на слова и раскрытию имён файлов.
          Оболочка выполняет раскрытие тильды, раскрытие параметров
          и переменных, арифметическое раскрытие, подстановку команд,
          подстановку процессов и удаление кавычек на этих словах.
          Условные операторы, такие как **-f**, должны быть не
          процитированы, чтобы быть распознанными как примитивы.

          При использовании с **[[** операторы **<** и **>** сортируют
          лексикографически с использованием текущей локали.

          Когда используются операторы **==** и **!=**, строка справа от
          оператора рассматривается как шаблон и сопоставляется
          согласно правилам, описанным ниже в разделе **Сопоставление**
          **с образцом**, как если бы опция оболочки **extglob** была
          включена. Оператор **=** эквивалентен **==**. Если включена
          опция оболочки **nocasematch**, сопоставление выполняется без
          учёта регистра буквенных символов. Возвращаемое значение
          равно 0, если строка соответствует (**==**) или не соответствует
          (**!=**) шаблону, и 1 в противном случае. Если какая-либо
          часть шаблона процитирована, процитированная часть
          сопоставляется как строка: каждый символ в процитированной
          части сопоставляется сам с собой, вместо того чтобы иметь
          какое-либо специальное значение сопоставления с образцом.

          Дополнительный бинарный оператор **=~** доступен с тем же
          приоритетом, что и **==** и **!=**. Когда он используется,
          строка справа от оператора рассматривается как расширенное
          регулярное выражение POSIX и сопоставляется соответствующим
          образом (используя интерфейсы POSIX _regcomp_ и _regexec_,
          обычно описываемые в [regex(3)](https://man7.org/linux/man-pages/man3/regex.3.html)). Возвращаемое значение равно 0, если
          строка соответствует шаблону, и 1 в противном случае. Если
          регулярное выражение синтаксически некорректно, возвращаемое
          значение условного выражения равно 2. Если включена опция
          оболочки **nocasematch**, сопоставление выполняется без учёта
          регистра буквенных символов.

          Если какая-либо часть шаблона процитирована, процитированная
          часть сопоставляется буквально, как описано выше. Если шаблон
          хранится в переменной оболочки, цитирование раскрытия
          переменной заставляет весь шаблон сопоставляться буквально.
          Обрабатывайте выражения в квадратных скобках в регулярных
          выражениях с осторожностью, поскольку обычные символы
          цитирования и шаблона теряют свои значения между скобками.

          Сопоставление успешно, если шаблон соответствует любой части
          строки. Закрепите шаблон с использованием операторов
          регулярных выражений **^** и **$**, чтобы заставить его
          соответствовать всей строке.

          Массивная переменная **BASH_REMATCH** записывает, какие части
          строки соответствовали шаблону. Элемент **BASH_REMATCH** с
          индексом 0 содержит часть строки, соответствующую всему
          регулярному выражению. Подстроки, соответствующие
          подвыражениям в круглых скобках внутри регулярного выражения,
          сохраняются в оставшихся индексах **BASH_REMATCH**. Элемент
          **BASH_REMATCH** с индексом _n_ — это часть строки,
          соответствующая _n_-му подвыражению в круглых скобках. **Bash**
          устанавливает **BASH_REMATCH** в глобальной области видимости;
          объявление её как локальной переменной приведёт к
          неожиданным результатам.

          Выражения могут быть объединены с использованием следующих
          операторов, перечисленных в порядке убывания приоритета:

          **(** _expression_ **)**
                 Возвращает значение _expression_. Это может быть
                 использовано для переопределения обычного приоритета
                 операторов.
          **!** _expression_
                 Истинно, если _expression_ ложно.
          _expression1_ **&&** _expression2_
                 Истинно, если оба _expression1_ и _expression2_ истинны.
          _expression1_ **||** _expression2_
                 Истинно, если либо _expression1_, либо _expression2_
                 истинны.

          Операторы **&&** и **||** не вычисляют _expression2_, если
          значение _expression1_ достаточно для определения возвращаемого
          значения всего условного выражения.

   **for** _name_ [ [ **in** _word ..._ ] ; ] **do** _list_ ; **done**
          Сначала раскрывается список слов после **in**, генерируя
          список элементов. Затем переменная _name_ устанавливается в
          каждый элемент этого списка по очереди, и _list_ выполняется
          каждый раз. Если **in** _word_ опущено, команда **for** выполняет
          _list_ один раз для каждого установленного позиционного
          параметра (см. **ПАРАМЕТРЫ** ниже). Возвращаемым статусом
          является статус завершения последней выполненной команды.
          Если раскрытие элементов после **in** приводит к пустому
          списку, никакие команды не выполняются, и возвращаемый
          статус равен 0.

   **for** (( _expr1_ ; _expr2_ ; _expr3_ )) [;] **do** _list_ ; **done**
          Сначала вычисляется арифметическое выражение _expr1_ согласно
          правилам, описанным ниже в разделе **АРИФМЕТИЧЕСКИЕ ВЫЧИСЛЕНИЯ**.
          Затем повторно вычисляется арифметическое выражение _expr2_,
          пока оно не станет равным нулю. Каждый раз, когда _expr2_
          вычисляется в ненулевое значение, выполняется _list_ и
          вычисляется арифметическое выражение _expr3_. Если любое
          выражение опущено, оно ведёт себя так, как если бы оно
          вычислялось в 1. Возвращаемым значением является статус
          завершения последней команды в _list_, которая выполняется,
          или ненулевое, если любое из выражений неверно.

          Используйте встроенные команды **break** и **continue** (см.
          **ВСТРОЕННЫЕ КОМАНДЫ ОБОЛОЧКИ** ниже) для управления выполнением
          цикла.

   **select** _name_ [ **in** _word_ ] ; **do** _list_ ; **done**
          Сначала раскрывается список слов после **in**, генерируя
          список элементов, и выводится набор раскрытых слов в
          стандартный вывод ошибок, каждое предваряемое номером.
          Если **in** _word_ опущено, выводятся позиционные параметры
          (см. **ПАРАМЕТРЫ** ниже). **select** затем отображает приглашение
          **PS3** и читает строку из стандартного ввода. Если строка
          состоит из номера, соответствующего одному из отображённых
          слов, то **select** устанавливает значение _name_ в это слово.
          Если строка пуста, **select** снова отображает слова и
          приглашение. Если читается EOF, **select** завершается и
          возвращает 1. Любое другое значение устанавливает _name_ в
          null. Прочитанная строка сохраняется в переменной **REPLY**.
          _list_ выполняется после каждого выбора, пока не выполнится
          команда **break**. Статус завершения **select** — это статус
          завершения последней выполненной команды в _list_, или ноль,
          если не было выполнено ни одной команды.

   **case** _word_ **in** [ [(] _pattern_ [ **|** _pattern_ ] ... ) _list_ ;; ] ... **esac**
          Команда **case** сначала раскрывает _word_ и пытается
          сопоставить его с каждым _pattern_ по очереди, переходя от
          первого к последнему, используя правила сопоставления,
          описанные в разделе **Сопоставление с образцом** ниже.
          Список шаблонов — это набор из одного или более шаблонов,
          разделённых , и оператор ) завершает список шаблонов.
          _word_ раскрывается с использованием раскрытия тильды,
          раскрытия параметров и переменных, арифметического раскрытия,
          подстановки команд, подстановки процессов и удаления кавычек.
          Каждый проверяемый _pattern_ раскрывается с использованием
          раскрытия тильды, раскрытия параметров и переменных,
          арифметического раскрытия, подстановки команд, подстановки
          процессов и удаления кавычек. Если включена опция оболочки
          **nocasematch**, сопоставление выполняется без учёта регистра
          буквенных символов. _Пункт_ — это список шаблонов и связанный
          с ним _список_.

          Когда совпадение найдено, **case** выполняет соответствующий
          _list_. Если оператор **;;** завершает пункт case, команда
          **case** завершается после первого совпадения. Использование
          **;&** вместо **;;** вызывает продолжение выполнения со
          _списком_, связанным со следующим списком шаблонов.
          Использование **;;&** вместо **;;** заставляет оболочку
          проверить следующий список шаблонов в операторе, если таковой
          имеется, и выполнить любой связанный _list_, если совпадение
          успешно, продолжая выполнение оператора case, как если бы
          список шаблонов не совпал. Статус завершения равен нулю,
          если ни один шаблон не совпал.

          В противном случае это статус завершения последней команды,
          выполненной в последнем выполненном _списке_.

   **if** _list_; **then** _list_; [ **elif** _list_; **then** _list_; ] ... [ **else** _list_; ]
   **fi**
          Выполняется **if** _list_. Если его статус завершения равен
          нулю, выполняется **then** _list_. В противном случае каждый
          **elif** _list_ выполняется по очереди, и если его статус
          завершения равен нулю, выполняется соответствующий **then**
          _list_ и команда завершается. В противном случае выполняется
          **else** _list_, если он присутствует. Статус завершения —
          это статус завершения последней выполненной команды или
          ноль, если ни одно условие не было истинным.

   **while** _list-1_; **do** _list-2_; **done**
   **until** _list-1_; **do** _list-2_; **done**
          Команда **while** непрерывно выполняет список _list-2_, пока
          последняя команда в списке _list-1_ возвращает статус
          завершения ноль. Команда **until** идентична команде **while**,
          за исключением того, что проверка инвертирована: _list-2_
          выполняется, пока последняя команда в _list-1_ возвращает
          ненулевой статус завершения. Статус завершения команд
          **while** и **until** — это статус завершения последней
          выполненной команды в _list-2_ или ноль, если ни одна не
          была выполнена.
### Сопроцессы
      Сопроцесс — это команда оболочки, предваряемая зарезервированным
      словом coproc. Сопроцесс выполняется асинхронно в подоболочке,
      как если бы команда была завершена оператором управления &, с
      установлением двустороннего конвейера между выполняющей оболочкой
      и сопроцессом.
   Синтаксис сопроцесса:

          **coproc** [_NAME_] _command_ [_redirections_]

   Это создаёт сопроцесс с именем _NAME_. _command_ может быть либо
   простой командой, либо составной командой (см. выше). _NAME_ — это
   имя переменной оболочки. Если _NAME_ не указано, имя по умолчанию —
   **COPROC**.

   Рекомендуемая форма для сопроцесса:

          **coproc** _NAME_ { _command_ [_redirections_]; }

   Эта форма предпочтительна, потому что простые команды всегда
   приводят к тому, что сопроцесс называется **COPROC**, и она проще
   в использовании и более полная, чем другие составные команды.

   Если _command_ является составной командой, _NAME_ необязательно.
   Слово, следующее за **coproc**, определяет, интерпретируется ли это
   слово как имя переменной: оно интерпретируется как _NAME_, если это
   не зарезервированное слово, которое вводит составную команду.
   Если _command_ является простой командой, _NAME_ не разрешено; это
   сделано, чтобы избежать путаницы между _NAME_ и первым словом
   простой команды.

   Когда сопроцесс выполняется, оболочка создаёт массивную переменную
   (см. **Массивы** ниже) с именем _NAME_ в контексте выполняющей
   оболочки. Стандартный вывод _command_ соединяется через конвейер с
   файловым дескриптором в выполняющей оболочке, и этот файловый
   дескриптор присваивается _NAME_[0]. Стандартный ввод _command_
   соединяется через конвейер с файловым дескриптором в выполняющей
   оболочке, и этот файловый дескриптор присваивается _NAME_[1].
   Этот конвейер устанавливается перед любыми перенаправлениями,
   указанными командой (см. **ПЕРЕНАПРАВЛЕНИЕ** ниже). Файловые
   дескрипторы могут использоваться в качестве аргументов команд
   оболочки и перенаправлений с использованием стандартного раскрытия
   слов. За исключением созданных для выполнения подстановки команд и
   процессов, файловые дескрипторы недоступны в подоболочках.

   Идентификатор процесса оболочки, порождённой для выполнения
   сопроцесса, доступен как значение переменной _NAME__PID. Встроенная
   команда **wait** может использоваться для ожидания завершения
   сопроцесса.

   Поскольку сопроцесс создаётся как асинхронная команда, команда
   **coproc** всегда возвращает успех. Возвращаемым статусом
   сопроцесса является статус завершения _command_.
   ### Определения функций оболочки
      Функция оболочки — это объект, который вызывается как простая
      команда и выполняет составную команду с новым набором позиционных
      параметров. Функции оболочки объявляются следующим образом:
   _fname_ () _compound-command_ [_redirection_]
   **function** _fname_ [()] _compound-command_ [_redirection_]
          Это определяет функцию с именем _fname_. Зарезервированное
          слово **function** необязательно. Если указано зарезервированное
          слово **function**, круглые скобки необязательны. _Тело_
          функции — это составная команда _compound-command_ (см.
          **Составные команды** выше). Эта команда обычно является
          _списком_ команд между { и }, но может быть любой командой,
          перечисленной в **Составные команды** выше. Если используется
          зарезервированное слово **function**, но круглые скобки не
          указаны, рекомендуется использовать фигурные скобки.
          _compound-command_ выполняется всякий раз, когда _fname_
          указывается как имя простой команды. В режиме posix _fname_
          должно быть допустимым _именем_ оболочки и не может быть
          именем одного из POSIX _специальных встроенных команд_.
          В режиме по умолчанию имя функции может быть любым
          непроцитированным словом оболочки, которое не содержит **$**.

   Любые перенаправления (см. **ПЕРЕНАПРАВЛЕНИЕ** ниже), указанные при
   определении функции, выполняются при выполнении функции.

   Статус завершения определения функции равен нулю, если не возникает
   синтаксическая ошибка или если функция только для чтения с тем же
   именем уже существует. При выполнении статус завершения функции
   равен статусу завершения последней выполненной команды в теле.
   (См. **ФУНКЦИИ** ниже.)
   ## Комментарии
   В неинтерактивной оболочке или в интерактивной оболочке, у которой включена опция interactive_comments для встроенной команды shopt (см. ВСТРОЕННЫЕ КОМАНДЫ ОБОЛОЧКИ ниже), слово, начинающееся с #, вводит комментарий. Слово начинается в начале строки, после непроцитированных пробельных символов или после оператора. Комментарий приводит к тому, что это слово и все оставшиеся символы в этой строке игнорируются. Интерактивная оболочка без включённой опции interactive_comments не позволяет комментарии. Опция interactive_comments по умолчанию включена в интерактивных оболочках.
## ЦИТИРОВАНИЕ
Цитирование используется для удаления специального значения определённых символов или слов для оболочки. Цитирование может использоваться для отключения специальной обработки специальных символов, для предотвращения распознавания зарезервированных слов как таковых и для предотвращения раскрытия параметров.

Каждый из метасимволов, перечисленных выше в разделе ОПРЕДЕЛЕНИЯ, имеет специальное значение для оболочки и должен быть процитирован, если должен представлять сам себя.

Когда используются средства расширения истории команд (см. РАСШИРЕНИЕ ИСТОРИИ ниже), символ расширения истории, обычно !, должен быть процитирован, чтобы предотвратить расширение истории.

Существует четыре механизма цитирования: экранирующий символ, одинарные кавычки, двойные кавычки и доллар-одинарные кавычки.

Непроцитированная обратная косая черта (***) является экранирующим символом. Она сохраняет буквальное значение следующего за ней символа, удаляя любое специальное значение, за исключением <newline>. Если появляется пара ***<newline>, и сама обратная косая черта не процитирована, ****<newline> рассматривается как продолжение строки (то есть удаляется из входного потока и фактически игнорируется).

Заключение символов в одинарные кавычки сохраняет буквальное значение каждого символа внутри кавычек. Одинарная кавычка не может встречаться между одинарными кавычками, даже если ей предшествует обратная косая черта.

Заключение символов в двойные кавычки сохраняет буквальное значение всех символов внутри кавычек, за исключением $, **, **\**, и, когда включено расширение истории, **!**. Когда оболочка находится в режиме posix, **!** не имеет специального значения внутри двойных кавычек, даже если расширение истории включено. Символы **$** и ** сохраняют своё специальное значение внутри двойных кавычек. Обратная косая черта сохраняет своё специальное значение только тогда, когда за ней следует один из символов: $, `, ", ****, или <newline>. Обратные косые черты, предшествующие символам без специального значения, остаются без изменений.

Двойная кавычка может быть процитирована внутри двойных кавычек, если перед ней поставить обратную косую черту. Если включено, расширение истории будет выполнено, если только !, появляющийся в двойных кавычках, не экранирован с помощью обратной косой черты. Обратная косая черта, предшествующая !, не удаляется.

Специальные параметры ***** и @ имеют специальное значение внутри двойных кавычек (см. ПАРАМЕТРЫ ниже).

Последовательности символов вида $'string' рассматриваются как специальный вариант одинарных кавычек. Последовательность раскрывается в string, причём экранированные обратной косой чертой символы в string заменяются, как указано стандартом ANSI C. Экранирующие последовательности обратной косой черты, если присутствуют, декодируются следующим образом:

\a сигнал (звонок)
\b возврат на шаг
\e
\E символ escape
\f прогон страницы
\n новая строка
\r возврат каретки
\t горизонтальная табуляция
\v вертикальная табуляция
\ обратная косая черта
' одинарная кавычка
" двойная кавычка
? знак вопроса
****nnn восьмибитный символ, значение которого является восьмеричным значением nnn (от одной до трёх восьмеричных цифр).
\xHH восьмибитный символ, значение которого является шестнадцатеричным значением HH (одна или две шестнадцатеричные цифры).
\uHHHH Символ Unicode (ISO/IEC 10646), значение которого является шестнадцатеричным значением HHHH (от одной до четырёх шестнадцатеричных цифр).
\UHHHHHHHH
Символ Unicode (ISO/IEC 10646), значение которого является шестнадцатеричным значением HHHHHHHH (от одной до восьми шестнадцатеричных цифр).
\cx управляющий символ x.

Раскрытый результат заключается в одинарные кавычки, как если бы знак доллара не присутствовал.

Перевод строк

Строка в двойных кавычках, перед которой стоит знак доллара ($"string"), заставляет строку переводиться в соответствии с текущей локалью. Инфраструктура gettext выполняет поиск и перевод, используя переменные оболочки LC_MESSAGES, TEXTDOMAINDIR и TEXTDOMAIN. Если текущая локаль — C или POSIX, если нет доступных переводов или если строка не переведена, знак доллара игнорируется, и строка обрабатывается как заключённая в двойные кавычки, как описано выше. Это форма двойного цитирования, поэтому строка остаётся в двойных кавычках по умолчанию, независимо от того, переведена и заменена ли она. Если включена опция noexpand_translation с помощью встроенной команды shopt, переведённые строки заключаются в одинарные кавычки вместо двойных. См. описание shopt ниже в разделе ВСТРОЕННЫЕ КОМАНДЫ ОБОЛОЧКИ.
## ПАРАМЕТРЫ
Параметр — это сущность, которая хранит значения. Это может быть имя, число или один из специальных символов, перечисленных ниже в разделе Специальные параметры. Переменная — это параметр, обозначенный именем. Переменная имеет значение и ноль или более атрибутов. Атрибуты назначаются с помощью встроенной команды declare (см. declare ниже в разделе ВСТРОЕННЫЕ КОМАНДЫ ОБОЛОЧКИ). Встроенные команды export и readonly назначают определённые атрибуты.

Параметр считается установленным, если ему присвоено значение. Пустая строка является допустимым значением. После того как переменная установлена, она может быть снята только с помощью встроенной команды unset (см. ВСТРОЕННЫЕ КОМАНДЫ ОБОЛОЧКИ ниже).

Переменной присваивается значение с помощью оператора вида: `name=[value]`
Если value не указано, переменной присваивается пустая строка. Все значения подвергаются раскрытию тильды, раскрытию параметров и переменных, подстановке команд, арифметическому раскрытию и удалению кавычек (см. РАСКРЫТИЕ ниже). Если переменная имеет атрибут integer, то value вычисляется как арифметическое выражение, даже если не используется расширение $((...)) (см. Арифметическое раскрытие ниже). Разбиение на слова и раскрытие имён файлов не выполняются. Операторы присваивания также могут появляться в качестве аргументов встроенных команд alias, declare, typeset, export, readonly и local (команды объявления). В режиме posix эти встроенные команды могут появляться в команде после одного или более экземпляров встроенной команды command и сохранять эти свойства операторов присваивания.

В контексте, где оператор присваивания присваивает значение переменной оболочки или индексу массива, оператор «+=» добавляет к предыдущему значению переменной или увеличивает его. Это включает аргументы команд объявления, таких как declare, которые принимают операторы присваивания. Когда «+=» применяется к переменной, для которой установлен атрибут integer, текущее значение переменной и value вычисляются как арифметические выражения, и сумма результатов присваивается как значение переменной. Текущее значение обычно является целочисленной константой, но может быть выражением. Когда «+=» применяется к переменной-массиву с использованием составного присваивания (см. Массивы ниже), значение переменной не снимается (как при использовании «=»), и новые значения добавляются в массив, начиная с индекса на единицу больше максимального индекса массива (для индексированных массивов) или добавляются как дополнительные пары ключ-значение в ассоциативном массиве. Когда применяется к строковой переменной, value раскрывается и добавляется к значению переменной.

Переменной может быть назначен атрибут nameref с помощью опции -n встроенных команд declare или local (см. описания declare и local ниже) для создания nameref, или ссылки на другую переменную. Это позволяет манипулировать переменными косвенно. Всякий раз, когда ссылаются на nameref-переменную, присваивают ей значение, снимают её или изменяют её атрибуты (кроме использования или изменения самого атрибута nameref), операция фактически выполняется с переменной, указанной значением nameref-переменной. Nameref обычно используется внутри функций оболочки для ссылки на переменную, имя которой передаётся в качестве аргумента функции. Например, если имя переменной передаётся в функцию оболочки в качестве первого аргумента, выполнение `declare -n ref=$1` внутри функции создаёт локальную nameref-переменную ref, значение которой является именем переменной, переданным в качестве первого аргумента. Ссылки и присваивания для ref, а также изменения его атрибутов рассматриваются как ссылки, присваивания и изменения атрибутов переменной, имя которой было передано как $1. Если управляющая переменная в цикле for имеет атрибут nameref, список слов может быть списком переменных оболочки, и для каждого слова в списке по очереди устанавливается ссылка на имя при выполнении цикла. Переменные-массивы не могут иметь атрибут nameref. Однако nameref-переменные могут ссылаться на переменные-массивы и индексированные переменные-массивы. Nameref могут быть сняты с помощью опции -n встроенной команды unset. В противном случае, если unset выполняется с именем nameref-переменной в качестве аргумента, переменная, на которую ссылается nameref-переменная, снимается.

При запуске оболочка читает своё окружение и создаёт переменную оболочки для каждой переменной окружения, которая имеет допустимое имя, как описано ниже (см. ОКРУЖЕНИЕ).

Позиционные параметры

Позиционный параметр — это параметр, обозначенный одной или более цифрами, за исключением единственной цифры 0. Позиционные параметры назначаются из аргументов оболочки при её вызове и могут быть переназначены с помощью встроенной команды set. Позиционным параметрам не могут быть присвоены значения с помощью операторов присваивания. Позиционные параметры временно заменяются при выполнении функции оболочки (см. ФУНКЦИИ ниже).

Когда раскрывается позиционный параметр, состоящий более чем из одной цифры, он должен быть заключён в фигурные скобки (см. РАСКРЫТИЕ ниже). Без фигурных скобок цифра, следующая за $, может ссылаться только на один из первых девяти позиционных параметров ($1-$9) или специальный параметр $0 (см. следующий раздел).

Специальные параметры

Оболочка обрабатывает несколько параметров специальным образом. На эти параметры можно только ссылаться; присваивание им не допускается. Специальные параметры обозначаются одним из следующих символов.

***** ($*) Раскрывается в позиционные параметры, начиная с первого. Когда раскрытие не находится внутри двойных кавычек, каждый позиционный параметр раскрывается в отдельное слово. В контекстах, где выполняется разбиение на слова, эти слова подвергаются дальнейшему разбиению на слова и раскрытию имён файлов. Когда раскрытие происходит внутри двойных кавычек, оно раскрывается в одно слово, значение которого состоит из значений каждого параметра, разделённых первым символом переменной IFS. То есть "$*" эквивалентно "$1"c"$2"c..., где c — первый символ значения переменной IFS. Если IFS не установлена, параметры разделяются пробелами. Если IFS равна null, параметры объединяются без разделителей.

@ ($@) Раскрывается в позиционные параметры, начиная с первого. В контекстах, где выполняется разбиение на слова, каждый позиционный параметр раскрывается в отдельное слово; если не в двойных кавычках, эти слова подвергаются разбиению на слова. В контекстах, где разбиение на слова не выполняется, например, в части значения оператора присваивания, это раскрывается в одно слово, где каждый позиционный параметр разделён пробелом. Когда раскрытие происходит внутри двойных кавычек и выполняется разбиение на слова, каждый параметр раскрывается в отдельное слово. То есть "$@" эквивалентно "$1" "$2" .... Если двойное раскрытие происходит внутри слова, раскрытие первого параметра объединяется с раскрытием начальной части исходного слова, а раскрытие последнего параметра объединяется с раскрытием конечной части исходного слова. Когда нет позиционных параметров, "$@" и $@ раскрываются в ничто (т.е. они удаляются).

# ($#) Раскрывается в количество позиционных параметров в десятичном виде.

? ($?) Раскрывается в статус завершения последней выполненной команды.

- ($-) Раскрывается в текущие флаги опций, указанные при вызове, встроенной командой set или установленные самой оболочкой (например, опция -i).

$ ($$) Раскрывается в идентификатор процесса оболочки. В подоболочке раскрывается в идентификатор процесса родительской оболочки, а не подоболочки.

! ($!) Раскрывается в идентификатор процесса задания, которое было последним помещено в фон, независимо от того, было ли оно выполнено как асинхронная команда или с использованием встроенной команды bg (см. УПРАВЛЕНИЕ ЗАДАНИЯМИ ниже).

0 ($0) Раскрывается в имя оболочки или скрипта оболочки. Устанавливается при инициализации оболочки. Если bash вызывается с файлом команд, $0 устанавливается в имя этого файла. Если bash запускается с опцией -c, то $0 устанавливается в первый аргумент после строки для выполнения, если он присутствует. В противном случае устанавливается в имя файла, использованное для вызова bash, как задано аргументом ноль.

Переменные оболочки

Оболочка устанавливает следующие переменные:

_ ($_) Имеет ряд значений в зависимости от контекста. При запуске оболочки _ устанавливается в путь, использованный для вызова оболочки или выполняемого скрипта оболочки, переданный в окружении или списке аргументов. Впоследствии она раскрывается в последний аргумент предыдущей простой команды, выполненной в foreground, после раскрытия. Также устанавливается в полный путь, использованный для вызова каждой выполненной команды, и помещается в окружение, экспортируемое в эту команду. При проверке почты $_ раскрывается в имя текущего проверяемого почтового файла.

BASH Раскрывается в полное имя файла, использованное для вызова этого экземпляра bash.

BASHOPTS
Список включённых опций оболочки, разделённых двоеточиями. Каждое слово в списке является допустимым аргументом для опции -s встроенной команды shopt (см. ВСТРОЕННЫЕ КОМАНДЫ ОБОЛОЧКИ ниже). Опции, появляющиеся в BASHOPTS, — это те, которые shopt сообщает как on. Если эта переменная присутствует в окружении при запуске bash, оболочка включает каждую опцию из списка до чтения каких-либо стартовых файлов. Если эта переменная экспортируется, дочерние оболочки включат каждую опцию из списка. Эта переменная только для чтения.

BASHPID
Раскрывается в идентификатор процесса текущего процесса bash. Это отличается от $$ в определённых обстоятельствах, например, в подоболочках, которые не требуют повторной инициализации bash. Присваивания BASHPID не имеют эффекта. Если BASHPID снята, она теряет свои специальные свойства, даже если впоследствии будет установлена.

BASH_ALIASES
Ассоциативный массив, элементы которого соответствуют внутреннему списку псевдонимов, поддерживаемому встроенной командой alias. Элементы, добавленные в этот массив, появляются в списке псевдонимов; однако снятие элементов массива в настоящее время не удаляет псевдонимы из списка псевдонимов. Если BASH_ALIASES снята, она теряет свои специальные свойства, даже если впоследствии будет установлена.

BASH_ARGC
Массив, значения которого представляют количество параметров в каждом фрейме текущего стека вызовов выполнения bash. Количество параметров текущей подпрограммы (функции оболочки или скрипта, выполняемого с помощью . или source) находится вверху стека. При выполнении подпрограммы количество переданных параметров помещается в BASH_ARGC. Оболочка устанавливает BASH_ARGC только в расширенном режиме отладки (см. описание опции extdebug для встроенной команды shopt ниже). Установка extdebug после того, как оболочка начала выполнение скрипта, или обращение к этой переменной, когда extdebug не установлена, может привести к несогласованным значениям. Присваивания BASH_ARGC не имеют эффекта, и она не может быть снята.

BASH_ARGV
Массив, содержащий все параметры в текущем стеке вызовов выполнения bash. Последний параметр последнего вызова подпрограммы находится вверху стека; первый параметр начального вызова — внизу. При выполнении подпрограммы оболочка помещает предоставленные параметры в BASH_ARGV. Оболочка устанавливает BASH_ARGV только в расширенном режиме отладки (см. описание опции extdebug для встроенной команды shopt ниже). Установка extdebug после того, как оболочка начала выполнение скрипта, или обращение к этой переменной, когда extdebug не установлена, может привести к несогласованным значениям. Присваивания BASH_ARGV не имеют эффекта, и она не может быть снята.

BASH_ARGV0
При обращении эта переменная раскрывается в имя оболочки или скрипта оболочки (идентично $0; см. описание специального параметра 0 выше). Присваивание значения BASH_ARGV0 устанавливает $0 в то же значение. Если BASH_ARGV0 снята, она теряет свои специальные свойства, даже если впоследствии будет установлена.

BASH_CMDS
Ассоциативный массив, элементы которого соответствуют внутренней хеш-таблице команд, поддерживаемой встроенной командой hash. Добавление элементов в этот массив заставляет их появляться в хеш-таблице; однако снятие элементов массива в настоящее время не удаляет имена команд из хеш-таблицы. Если BASH_CMDS снята, она теряет свои специальные свойства, даже если впоследствии будет установлена.

BASH_COMMAND
Раскрывается в команду, которая в настоящее время выполняется или вот-вот будет выполнена, за исключением случаев, когда оболочка выполняет команду в результате trap, тогда это команда, выполняемая в момент trap. Если BASH_COMMAND снята, она теряет свои специальные свойства, даже если впоследствии будет установлена.

BASH_EXECUTION_STRING
Аргумент команды для опции вызова -c.

BASH_LINENO
Массив, элементы которого представляют номера строк в исходных файлах, где был вызван каждый соответствующий элемент FUNCNAME. ${BASH_LINENO[$i]} — это номер строки в исходном файле (${BASH_SOURCE[$i+1]}), где был вызван ${FUNCNAME[$i]} (или ${BASH_LINENO[$i-1]}, если ссылка находится внутри другой функции оболочки). Используйте LINENO, чтобы получить текущий номер строки. Присваивания BASH_LINENO не имеют эффекта, и она не может быть снята.

BASH_LOADABLES_PATH
Список каталогов, разделённых двоеточиями, в которых команда enable ищет динамически загружаемые встроенные команды.

BASH_MONOSECONDS
Каждый раз, когда эта переменная упоминается, она раскрывается в значение, возвращаемое монотонными часами системы, если они доступны. Если монотонных часов нет, это эквивалентно EPOCHSECONDS. Если BASH_MONOSECONDS снята, она теряет свои специальные свойства, даже если впоследствии будет установлена.

BASH_REMATCH
Массив, элементы которого назначаются бинарным оператором =~ в условной команде [[. Элемент с индексом 0 — это часть строки, соответствующая всему регулярному выражению. Элемент с индексом n — это часть строки, соответствующая n-му подвыражению в круглых скобках.

BASH_SOURCE
Массив, элементы которого представляют исходные имена файлов, где определены соответствующие имена функций оболочки в массиве FUNCNAME. Функция оболочки ${FUNCNAME[$i]} определена в файле ${BASH_SOURCE[$i]} и вызвана из ${BASH_SOURCE[$i+1]}. Присваивания BASH_SOURCE не имеют эффекта, и она не может быть снята.

BASH_SUBSHELL
Увеличивается на единицу внутри каждой подоболочки или среды подоболочки, когда оболочка начинает выполнение в этой среде. Начальное значение равно 0. Если BASH_SUBSHELL снята, она теряет свои специальные свойства, даже если впоследствии будет установлена.

BASH_TRAPSIG
Устанавливается в номер сигнала, соответствующий действию trap, выполняемому во время его выполнения. См. описание trap в разделе ВСТРОЕННЫЕ КОМАНДЫ ОБОЛОЧКИ ниже для информации о номерах сигналов и выполнении trap.

BASH_VERSINFO
Массив только для чтения, элементы которого содержат информацию о версии этого экземпляра bash. Значения, присвоенные элементам массива, следующие:
BASH_VERSINFO[0] Основной номер версии (релиз).
BASH_VERSINFO[1] Дополнительный номер версии.
BASH_VERSINFO[2] Уровень патча.
BASH_VERSINFO[3] Версия сборки.
BASH_VERSINFO[4] Статус выпуска (например, бета).
BASH_VERSINFO[5] Значение MACHTYPE.

BASH_VERSION
Раскрывается в строку, описывающую версию этого экземпляра bash (например, 5.2.37(3)-release).

COMP_CWORD
Индекс в ${COMP_WORDS} слова, содержащего текущую позицию курсора. Эта переменная доступна только в функциях оболочки, вызываемых средствами программируемого завершения (см. Программируемое завершение ниже).

COMP_KEY
Клавиша (или конечная клавиша последовательности клавиш), использованная для вызова текущей функции завершения. Эта переменная доступна только в функциях оболочки и внешних командах, вызываемых средствами программируемого завершения (см. Программируемое завершение ниже).

COMP_LINE
Текущая командная строка. Эта переменная доступна только в функциях оболочки и внешних командах, вызываемых средствами программируемого завершения (см. Программируемое завершение ниже).

COMP_POINT
Индекс текущей позиции курсора относительно начала текущей команды. Если текущая позиция курсора находится в конце текущей команды, значение этой переменной равно ${#COMP_LINE}. Эта переменная доступна только в функциях оболочки и внешних командах, вызываемых средствами программируемого завершения (см. Программируемое завершение ниже).

COMP_TYPE
Устанавливается в целочисленное значение, соответствующее типу попытки завершения, которая вызвала вызов функции завершения: TAB для обычного завершения, ? для вывода списка завершений после последовательных нажатий Tab, ! для вывода альтернатив при частичном завершении слова, @ для вывода списка завершений, если слово не изменено, или % для завершения через меню. Эта переменная доступна только в функциях оболочки и внешних командах, вызываемых средствами программируемого завершения (см. Программируемое завершение ниже).

COMP_WORDBREAKS
Набор символов, которые библиотека readline рассматривает как разделители слов при выполнении завершения слов. Если COMP_WORDBREAKS снята, она теряет свои специальные свойства, даже если впоследствии будет установлена.

COMP_WORDS
Массив (см. Массивы ниже), состоящий из отдельных слов в текущей командной строке. Строка разбивается на слова, как это сделал бы readline, используя COMP_WORDBREAKS, как описано выше. Эта переменная доступна только в функциях оболочки, вызываемых средствами программируемого завершения (см. Программируемое завершение ниже).

COPROC Массив (см. Массивы ниже), созданный для хранения файловых дескрипторов для вывода и ввода неименованного сопроцесса (см. Сопроцессы выше).

DIRSTACK
Массив (см. Массивы ниже), содержащий текущее содержимое стека каталогов. Каталоги появляются в стеке в том порядке, в котором они отображаются встроенной командой dirs. Присваивание элементам этого массива может использоваться для изменения каталогов, уже находящихся в стеке, но для добавления и удаления каталогов должны использоваться встроенные команды pushd и popd. Присваивание этой переменной не изменяет текущий каталог. Если DIRSTACK снята, она теряет свои специальные свойства, даже если впоследствии будет установлена.

EPOCHREALTIME
Каждый раз, когда этот параметр упоминается, он раскрывается в количество секунд с начала эпохи Unix (см. time(3)) как значение с плавающей точкой с микросекундной точностью. Присваивания EPOCHREALTIME игнорируются. Если EPOCHREALTIME снята, она теряет свои специальные свойства, даже если впоследствии будет установлена.

EPOCHSECONDS
Каждый раз, когда этот параметр упоминается, он раскрывается в количество секунд с начала эпохи Unix (см. time(3)). Присваивания EPOCHSECONDS игнорируются. Если EPOCHSECONDS снята, она теряет свои специальные свойства, даже если впоследствии будет установлена.

EUID Раскрывается в эффективный идентификатор пользователя текущего пользователя, инициализируется при запуске оболочки. Эта переменная только для чтения.

FUNCNAME
Массив, содержащий имена всех функций оболочки, находящихся в текущем стеке вызовов. Элемент с индексом 0 — это имя любой выполняемой в данный момент функции оболочки. Самый нижний элемент (с наибольшим индексом) — «main». Эта переменная существует только при выполнении функции оболочки. Присваивания FUNCNAME не имеют эффекта. Если FUNCNAME снята, она теряет свои специальные свойства, даже если впоследствии будет установлена.

Эта переменная может использоваться с BASH_LINENO и BASH_SOURCE. Каждый элемент FUNCNAME имеет соответствующие элементы в BASH_LINENO и BASH_SOURCE, описывающие стек вызовов. Например, ${FUNCNAME[$i]} была вызвана из файла ${BASH_SOURCE[$i+1]} на строке ${BASH_LINENO[$i]}. Встроенная команда caller отображает текущий стек вызовов с использованием этой информации.

GROUPS Массив, содержащий список групп, членом которых является текущий пользователь. Присваивания GROUPS не имеют эффекта. Если GROUPS снята, она теряет свои специальные свойства, даже если впоследствии будет установлена.

HISTCMD
Номер истории, или индекс в списке истории, текущей команды. Присваивания HISTCMD не имеют эффекта. Если HISTCMD снята, она теряет свои специальные свойства, даже если впоследствии будет установлена.

HOSTNAME
Автоматически устанавливается в имя текущего хоста.

HOSTTYPE
Автоматически устанавливается в строку, которая уникально описывает тип машины, на которой выполняется bash. Значение по умолчанию зависит от системы.

LINENO Каждый раз, когда этот параметр упоминается, оболочка подставляет десятичное число, представляющее текущий последовательный номер строки (начиная с 1) внутри скрипта или функции. Когда не в скрипте или функции, подставленное значение не гарантированно имеет смысл. Если LINENO снята, она теряет свои специальные свойства, даже если впоследствии будет установлена.

MACHTYPE
Автоматически устанавливается в строку, полностью описывающую тип системы, на которой выполняется bash, в стандартном формате GNU cpu-company-system. Значение по умолчанию зависит от системы.

MAPFILE
Массив (см. Массивы ниже), созданный для хранения текста, прочитанного встроенной командой mapfile, когда имя переменной не указано.

OLDPWD Предыдущий рабочий каталог, установленный командой cd.

OPTARG Значение последнего аргумента опции, обработанного встроенной командой getopts (см. ВСТРОЕННЫЕ КОМАНДЫ ОБОЛОЧКИ ниже).

OPTIND Индекс следующего аргумента, который будет обработан встроенной командой getopts (см. ВСТРОЕННЫЕ КОМАНДЫ ОБОЛОЧКИ ниже).

OSTYPE Автоматически устанавливается в строку, описывающую операционную систему, на которой выполняется bash. Значение по умолчанию зависит от системы.

PIPESTATUS
Массив (см. Массивы ниже), содержащий список значений статуса завершения команд из последнего выполненного конвейера в foreground, который может состоять только из простой команды (см. ГРАММАТИКА ОБОЛОЧКИ выше). Bash устанавливает PIPESTATUS после выполнения многозвенных конвейеров, конвейеров с временем и отрицанием, простых команд, подоболочек, созданных с помощью оператора (, составных команд [[ и ((, и после ошибок, которые приводят к прерыванию выполнения команд оболочкой.

PPID Идентификатор процесса родителя оболочки. Эта переменная только для чтения.

PWD Текущий рабочий каталог, установленный командой cd.

RANDOM Каждый раз, когда этот параметр упоминается, он раскрывается в случайное целое число от 0 до 32767. Присваивание значения RANDOM инициализирует (задаёт начальное значение) последовательность случайных чисел. Задание одного и того же начального значения для генератора случайных чисел производит одну и ту же последовательность значений. Если RANDOM снята, она теряет свои специальные свойства, даже если впоследствии будет установлена.

READLINE_ARGUMENT
Любой числовой аргумент, данный команде readline, которая была определена с использованием «bind -x» (см. ВСТРОЕННЫЕ КОМАНДЫ ОБОЛОЧКИ ниже) при её вызове.

READLINE_LINE
Содержимое буфера строки readline, для использования с «bind -x» (см. ВСТРОЕННЫЕ КОМАНДЫ ОБОЛОЧКИ ниже).

READLINE_MARK
Позиция метки (сохранённой точки вставки) в буфере строки readline, для использования с «bind -x» (см. ВСТРОЕННЫЕ КОМАНДЫ ОБОЛОЧКИ ниже). Символы между точкой вставки и меткой часто называют областью.

READLINE_POINT
Позиция точки вставки в буфере строки readline, для использования с «bind -x» (см. ВСТРОЕННЫЕ КОМАНДЫ ОБОЛОЧКИ ниже).

REPLY Устанавливается в строку ввода, прочитанную встроенной командой read, когда аргументы не предоставлены.

SECONDS
Каждый раз, когда этот параметр упоминается, он раскрывается в количество секунд с момента вызова оболочки. Если значение присвоено SECONDS, значение, возвращаемое при последующих обращениях, — это количество секунд с момента присваивания плюс присвоенное значение. Количество секунд при вызове оболочки и текущее время всегда определяются запросом системных часов с разрешением в одну секунду. Если SECONDS снята, она теряет свои специальные свойства, даже если впоследствии будет установлена.

SHELLOPTS
Список включённых опций оболочки, разделённых двоеточиями. Каждое слово в списке является допустимым аргументом для опции -o встроенной команды set (см. ВСТРОЕННЫЕ КОМАНДЫ ОБОЛОЧКИ ниже). Опции, появляющиеся в SHELLOPTS, — это те, которые set -o сообщает как on. Если эта переменная присутствует в окружении при запуске bash, оболочка включает каждую опцию из списка до чтения каких-либо стартовых файлов. Если эта переменная экспортируется, дочерние оболочки включат каждую опцию из списка. Эта переменная только для чтения.

SHLVL Увеличивается на единицу каждый раз, когда запускается экземпляр bash.

SRANDOM
Каждый раз, когда она упоминается, эта переменная раскрывается в 32-битное псевдослучайное число. Генератор случайных чисел нелинеен на системах, поддерживающих /dev/urandom или arc4random(3), поэтому каждое возвращаемое число не связано с предыдущими числами. Генератор случайных чисел не может быть инициализирован начальным значением, поэтому присваивания этой переменной не имеют эффекта. Если SRANDOM снята, она теряет свои специальные свойства, даже если впоследствии будет установлена.

UID Раскрывается в идентификатор пользователя текущего пользователя, инициализируется при запуске оболочки. Эта переменная только для чтения.

Оболочка использует следующие переменные. В некоторых случаях bash присваивает переменной значение по умолчанию; эти случаи отмечены ниже.

BASH_COMPAT
Значение используется для установки уровня совместимости оболочки. См. РЕЖИМ СОВМЕСТИМОСТИ ОБОЛОЧКИ ниже для описания различных уровней совместимости и их эффектов. Значение может быть десятичным числом (например, 4.2) или целым числом (например, 42), соответствующим желаемому уровню совместимости. Если BASH_COMPAT не установлена или установлена в пустую строку, уровень совместимости устанавливается в значение по умолчанию для текущей версии. Если BASH_COMPAT установлена в значение, которое не является одним из допустимых уровней совместимости, оболочка выводит сообщение об ошибке и устанавливает уровень совместимости в значение по умолчанию для текущей версии. Подмножество допустимых значений соответствует уровням совместимости, описанным ниже в разделе РЕЖИМ СОВМЕСТИМОСТИ ОБОЛОЧКИ. Например, 4.2 и 42 — допустимые значения, соответствующие опции compat42 shopt и устанавливающие уровень совместимости в 42. Текущая версия также является допустимым значением.

BASH_ENV
Если этот параметр установлен, когда bash выполняет скрипт оболочки, его раскрытое значение интерпретируется как имя файла, содержащего команды для инициализации оболочки перед чтением и выполнением команд из скрипта. Значение BASH_ENV подвергается раскрытию параметров, подстановке команд и арифметическому раскрытию перед интерпретацией как имя файла. PATH не используется для поиска результирующего имени файла.

BASH_XTRACEFD
Если установлена в целое число, соответствующее допустимому файловому дескриптору, bash записывает вывод трассировки, генерируемый при включении «set -x», в этот файловый дескриптор, а не в стандартный вывод ошибок. Файловый дескриптор закрывается, когда BASH_XTRACEFD снимается или ей присваивается новое значение. Снятие BASH_XTRACEFD или присваивание ей пустой строки приводит к отправке вывода трассировки в стандартный вывод ошибок. Обратите внимание, что установка BASH_XTRACEFD в 2 (файловый дескриптор стандартного вывода ошибок) и последующее её снятие приведёт к закрытию стандартного вывода ошибок.

CDPATH Путь поиска для команды cd. Это список каталогов, разделённых двоеточиями, где оболочка ищет каталоги, указанные в качестве аргументов команды cd. Пример значения: «.:~:/usr».

CHILD_MAX
Установите количество значений статуса завершённых дочерних процессов, которые оболочка должна запоминать. Bash не позволит уменьшить это значение ниже минимального, требуемого POSIX, и есть максимальное значение (в настоящее время 8192), которое не может быть превышено. Минимальное значение зависит от системы.

COLUMNS
Используется составной командой select для определения ширины терминала при выводе списков выбора. Автоматически устанавливается, если включена опция checkwinsize или в интерактивной оболочке при получении сигнала SIGWINCH.

COMPREPLY
Массив, из которого bash читает возможные завершения, сгенерированные функцией оболочки, вызванной средством программируемого завершения (см. Программируемое завершение ниже). Каждый элемент массива содержит одно возможное завершение.

EMACS Если bash находит эту переменную в окружении при запуске оболочки со значением «t», он предполагает, что оболочка работает в буфере оболочки Emacs, и отключает редактирование строк.

ENV Раскрывается и выполняется аналогично BASH_ENV (см. ЗАПУСК выше), когда интерактивная оболочка вызывается в режиме posix.

EXECIGNORE
Список шаблонов оболочки (см. Сопоставление с образцом), разделённых двоеточиями, определяющий набор имён файлов, которые игнорируются при поиске команд с использованием PATH. Файлы, полные пути которых соответствуют одному из этих шаблонов, не считаются исполняемыми файлами для целей завершения и выполнения команд через поиск в PATH. Это не влияет на поведение команд [, test и [[. Полные пути в хеш-таблице команд не подчиняются EXECIGNORE. Используйте эту переменную, чтобы игнорировать файлы общих библиотек, у которых установлен бит исполнения, но которые не являются исполняемыми файлами. Сопоставление шаблонов учитывает настройку опции оболочки extglob.

FCEDIT Редактор по умолчанию для встроенной команды fc.

FIGNORE
Список суффиксов, разделённых двоеточиями, которые следует игнорировать при выполнении завершения имён файлов (см. READLINE ниже). Имя файла, суффикс которого соответствует одной из записей в FIGNORE, исключается из списка совпавших имён файлов. Пример значения: «.o:~».

FUNCNEST
Если установлено числовое значение больше 0, определяет максимальный уровень вложенности функций. Вызовы функций, превышающие этот уровень вложенности, приводят к прерыванию текущей команды.

GLOBIGNORE
Список шаблонов, разделённых двоеточиями, определяющий набор имён файлов, которые игнорируются при раскрытии путей. Если имя файла, совпавшее с шаблоном раскрытия пути, также соответствует одному из шаблонов в GLOBIGNORE, оно удаляется из списка совпадений. Сопоставление шаблонов учитывает настройку опции оболочки extglob.

GLOBSORT
Управляет тем, как сортируются результаты раскрытия путей. Значение этой переменной определяет критерии сортировки и порядок сортировки результатов раскрытия путей. Если эта переменная не установлена или установлена в пустую строку, раскрытие путей использует историческое поведение сортировки по имени в возрастающем лексикографическом порядке, определённом переменной оболочки LC_COLLATE.

Если установлено, допустимое значение начинается с необязательного +, который игнорируется, или -, который меняет порядок сортировки с возрастающего на убывающий, за которым следует спецификатор сортировки. Допустимые спецификаторы сортировки: name, numeric, size, mtime, atime, ctime и blocks, которые сортируют файлы по имени, по имени в числовом, а не лексикографическом порядке, по размеру файла, времени модификации, времени доступа, времени изменения inode и количеству блоков соответственно. Если любые из не-имён ключей сравниваются как равные (например, если два файла имеют одинаковый размер), сортировка использует имя в качестве вторичного ключа сортировки.

Например, значение -mtime сортирует результаты в порядке убывания по времени модификации (сначала самые новые).

Спецификатор numeric рассматривает имена, состоящие исключительно из цифр, как числа и сортирует их, используя их числовое значение (так что «2» сортируется перед «10», например). При использовании numeric имена, содержащие не-цифры, сортируются после всех полностью цифровых имён и сортируются по имени, используя традиционное поведение.

Спецификатор сортировки nosort полностью отключает сортировку; bash возвращает результаты в том порядке, в котором они были прочитаны из файловой системы, игнорируя любой начальный -.

Если спецификатор сортировки отсутствует, по умолчанию используется name, поэтому значение + эквивалентно пустой строке, а значение - сортирует по имени в порядке убывания. Любое недопустимое значение восстанавливает историческое поведение сортировки.

HISTCONTROL
Список значений, разделённых двоеточиями, управляющих тем, как команды сохраняются в списке истории. Если список значений включает ignorespace, строки, которые начинаются с символа пробела, не сохраняются в списке истории. Значение ignoredups приводит к тому, что строки, соответствующие предыдущей записи истории, не сохраняются. Значение ignoreboth является сокращением для ignorespace и ignoredups. Значение erasedups приводит к удалению всех предыдущих строк, соответствующих текущей строке, из списка истории перед сохранением этой строки. Любое значение, не входящее в вышеуказанный список, игнорируется. Если HISTCONTROL не установлена или не включает допустимое значение, bash сохраняет все строки, прочитанные парсером оболочки, в списке истории, в зависимости от значения HISTIGNORE. Если первая строка многострочной составной команды была сохранена, вторая и последующие строки не проверяются и добавляются в историю независимо от значения HISTCONTROL. Если первая строка не была сохранена, вторая и последующие строки команды также не сохраняются.

HISTFILE
Имя файла, в котором сохраняется история команд (см. ИСТОРИЯ ниже). Bash присваивает значение по умолчанию ~/.bash_history. Если HISTFILE не установлена или равна null, оболочка не сохраняет историю команд при выходе.

HISTFILESIZE
Максимальное количество строк, содержащихся в файле истории. Когда этой переменной присваивается значение, файл истории при необходимости обрезается, чтобы содержать не более этого количества записей истории, удаляя самые старые записи. Если список истории содержит многострочные записи, файл истории может содержать больше строк, чем этот максимум, чтобы избежать оставления частичных записей истории. Файл истории также обрезается до этого размера после записи, когда оболочка выходит или с помощью встроенной команды history. Если значение равно 0, файл истории обрезается до нулевого размера. Нечисловые значения и числовые значения меньше нуля запрещают обрезку. Оболочка устанавливает значение по умолчанию в значение HISTSIZE после чтения любых стартовых файлов.

HISTIGNORE
Список шаблонов, разделённых двоеточиями, используемых для определения того, какие командные строки должны сохраняться в списке истории. Если командная строка соответствует одному из шаблонов в значении HISTIGNORE, она не сохраняется в списке истории. Каждый шаблон привязывается к началу строки и должен соответствовать всей строке (bash не подразумевает добавление «»). Каждый шаблон проверяется против строки после применения проверок, указанных HISTCONTROL. В дополнение к обычным символам сопоставления шаблонов оболочки «&» соответствует предыдущей строке истории. Обратная косая черта экранирует «&»; обратная косая черта удаляется перед попыткой сопоставления. Если первая строка многострочной составной команды была сохранена, вторая и последующие строки не проверяются и добавляются в историю независимо от значения HISTIGNORE. Если первая строка не была сохранена, вторая и последующие строки команды также не сохраняются. Сопоставление шаблонов учитывает настройку опции оболочки extglob. HISTIGNORE включает в себя часть функций HISTCONTROL. Шаблон «&» идентичен «ignoredups», а шаблон «[ ]» идентичен «ignorespace». Объединение этих двух шаблонов, разделённых двоеточием, обеспечивает функциональность «ignoreboth».

HISTSIZE
Количество команд, которые следует запоминать в истории команд (см. ИСТОРИЯ ниже). Если значение равно 0, команды не сохраняются в списке истории. Числовые значения меньше нуля приводят к сохранению каждой команды в списке истории (нет ограничений). Оболочка устанавливает значение по умолчанию в 500 после чтения любых стартовых файлов.

HISTTIMEFORMAT
Если эта переменная установлена и не null, её значение используется как строка формата для strftime(3) для вывода временной метки, связанной с каждой записью истории, отображаемой встроенной командой history. Если эта переменная установлена, оболочка записывает временные метки в файл истории, чтобы они могли сохраняться между сеансами оболочки. Это использует символ комментария истории для отличия временных меток от других строк истории.

HOME Домашний каталог текущего пользователя; аргумент по умолчанию для встроенной команды cd. Значение этой переменной также используется при выполнении раскрытия тильды.

HOSTFILE
Содержит имя файла в том же формате, что и /etc/hosts, который должен быть прочитан, когда оболочке нужно завершить имя хоста. Список возможных завершений имени хоста может быть изменён во время работы оболочки; в следующий раз, когда будет предпринята попытка завершения имени хоста после изменения значения, bash добавляет содержимое нового файла к существующему списку. Если HOSTFILE установлена, но не имеет значения или не называет читаемый файл, bash пытается прочитать /etc/hosts, чтобы получить список возможных завершений имени хоста. Когда HOSTFILE снята, bash очищает список имён хостов.

IFS Внутренний разделитель полей, который используется для разбиения на слова после раскрытия и для разделения строк на слова с помощью встроенной команды read. Разбиение на слова описано ниже в разделе РАСКРЫТИЕ. Значение по умолчанию — «<пробел><табуляция><новая строка>».

IGNOREEOF
Управляет действием интерактивной оболочки при получении символа EOF в качестве единственного ввода. Если установлено, значение — это количество последовательных символов EOF, которые должны быть набраны как первые символы входной строки перед выходом bash. Если переменная установлена, но не имеет числового значения, или значение равно null, значение по умолчанию равно 10. Если она не установлена, EOF означает конец ввода для оболочки.

INPUTRC
Имя файла для стартового файла readline, переопределяющее значение по умолчанию ~/.inputrc (см. READLINE ниже).

INSIDE_EMACS
Если эта переменная появляется в окружении при запуске оболочки, bash предполагает, что он работает внутри буфера оболочки Emacs и может отключить редактирование строк в зависимости от значения TERM.

LANG Используется для определения категории локали для любой категории, не выбранной явно с переменной, начинающейся с LC_.

LC_ALL Эта переменная переопределяет значение LANG и любой другой переменной LC_, указывающей категорию локали.

LC_COLLATE
Эта переменная определяет порядок сортировки, используемый при сортировке результатов раскрытия путей, и определяет поведение диапазонных выражений, классов эквивалентности и последовательностей сортировки внутри раскрытия путей и сопоставления с образцом.

LC_CTYPE
Эта переменная определяет интерпретацию символов и поведение классов символов внутри раскрытия путей и сопоставления с образцом.

LC_MESSAGES
Эта переменная определяет локаль, используемую для перевода строк в двойных кавычках, перед которыми стоит $.

LC_NUMERIC
Эта переменная определяет категорию локали, используемую для форматирования чисел.

LC_TIME
Эта переменная определяет категорию локали, используемую для форматирования даты и времени.

LINES Используется составной командой select для определения длины столбца для вывода списков выбора. Автоматически устанавливается, если включена опция checkwinsize или в интерактивной оболочке при получении сигнала SIGWINCH.

MAIL Если значение установлено в имя файла или каталога и переменная MAILPATH не установлена, bash информирует пользователя о поступлении почты в указанный файл или каталог формата Maildir.

MAILCHECK
Указывает, как часто (в секундах) bash проверяет почту. По умолчанию — 60 секунд. Когда приходит время проверить почту, оболочка делает это перед отображением основного приглашения. Если эта переменная не установлена или установлена в значение, которое не является числом, большим или равным нулю, оболочка отключает проверку почты.

MAILPATH
Список имён файлов, разделённых двоеточиями, которые следует проверять на наличие почты. Сообщение, которое должно быть напечатано при поступлении почты в определённый файл, может быть указано путём разделения имени файла и сообщения с помощью «?». Когда используется в тексте сообщения, $_ раскрывается в имя текущего почтового файла. Например:

text
MAILPATH='/var/mail/bfox?"You have mail":~/shell-mail?"$_ has mail!"'
Bash может быть настроен на предоставление значения по умолчанию для этой переменной (по умолчанию значения нет), но расположение пользовательских почтовых файлов, которые он использует, зависит от системы (например, /var/mail/$USER).

OPTERR Если установлено значение 1, bash отображает сообщения об ошибках, сгенерированные встроенной командой getopts (см. ВСТРОЕННЫЕ КОМАНДЫ ОБОЛОЧКИ ниже). OPTERR инициализируется в 1 каждый раз при вызове оболочки или выполнении скрипта оболочки.

PATH Путь поиска для команд. Это список каталогов, разделённых двоеточиями, в которых оболочка ищет команды (см. ВЫПОЛНЕНИЕ КОМАНД ниже). Нулевая (null) директория в значении PATH указывает на текущий каталог. Нулевая директория может появиться как два смежных двоеточия или как начальное или конечное двоеточие. Путь по умолчанию зависит от системы и устанавливается администратором, устанавливающим bash. Обычное значение:

text
/usr/local/bin:/usr/local/sbin:/usr/bin:/usr/sbin:/bin:/sbin
POSIXLY_CORRECT
Если эта переменная находится в окружении при запуске bash, оболочка входит в режим posix до чтения стартовых файлов, как если бы была указана опция вызова --posix. Если она установлена во время работы оболочки, bash включает режим posix, как если бы была выполнена команда «set -o posix». Когда оболочка входит в режим posix, она устанавливает эту переменную, если она ещё не была установлена.

PROMPT_COMMAND
Если эта переменная установлена и является массивом, значение каждого установленного элемента выполняется как команда перед выдачей каждого основного приглашения. Если она установлена, но не является массивом, её значение используется как команда для выполнения.

PROMPT_DIRTRIM
Если установлено число больше нуля, значение используется как количество конечных компонентов каталога для сохранения при раскрытии escapes строк приглашения \w и \W (см. ПРИГЛАШЕНИЯ ниже). Удалённые символы заменяются многоточием.

PS0 Значение этого параметра раскрывается (см. ПРИГЛАШЕНИЯ ниже) и отображается интерактивными оболочками после чтения команды и перед её выполнением.

PS1 Значение этого параметра раскрывается (см. ПРИГЛАШЕНИЯ ниже) и используется как основная строка приглашения. Значение по умолчанию — «\s-\v$ ».

PS2 Значение этого параметра раскрывается, как и PS1, и используется как вторичная строка приглашения. По умолчанию — «> ».

PS3 Значение этого параметра используется как приглашение для команды select (см. ГРАММАТИКА ОБОЛОЧКИ выше).

PS4 Значение этого параметра раскрывается, как и PS1, и значение печатается перед каждой командой, которую bash отображает во время трассировки выполнения. Первый символ раскрытого значения PS4 повторяется несколько раз, если необходимо, чтобы указать несколько уровней косвенности. По умолчанию — «+ ».

SHELL Эта переменная раскрывается в полный путь к оболочке. Если она не установлена при запуске оболочки, bash присваивает ей полный путь к регистрационной оболочке текущего пользователя.

TIMEFORMAT
Значение этого параметра используется как строка формата, определяющая, как должна отображаться информация о времени для конвейеров с предшествующим зарезервированным словом time. Символ % вводит escape-последовательность, которая раскрывается в значение времени или другую информацию. Escape-последовательности и их значения следующие; квадратные скобки обозначают необязательные части.

%% Буквальный %.
%[p][l]R Затраченное время в секундах.
%[p][l]U Количество процессорных секунд, затраченных в пользовательском режиме.
%[p][l]S Количество процессорных секунд, затраченных в системном режиме.
%P Процент использования процессора, вычисленный как (%U + %S) / %R.

Необязательный p — это цифра, указывающая точность, количество дробных цифр после десятичной точки. Значение 0 приводит к тому, что десятичная точка и дробь не выводятся. time печатает не более шести цифр после десятичной точки; значения p больше 6 изменяются на 6. Если p не указан, time печатает три цифры после десятичной точки.

Необязательный l указывает более длинный формат, включая минуты, вида MM_m_SS._FF_s. Значение p определяет, включается ли дробная часть.

Если эта переменная не установлена, bash ведёт себя так, как если бы она имела значение $'\nreal\t%3lR\nuser\t%3lU\nsys\t%3lS'. Если значение равно null, bash не отображает никакой информации о времени. Конечный символ новой строки добавляется при отображении строки формата.

TMOUT Если установлено значение больше нуля, встроенная команда read использует значение как таймаут по умолчанию. Команда select завершается, если ввод не поступает после TMOUT секунд, когда ввод поступает с терминала. В интерактивной оболочке значение интерпретируется как количество секунд ожидания строки ввода после выдачи основного приглашения. Bash завершается после ожидания этого количества секунд, если полная строка ввода не поступает.

TMPDIR Если установлено, bash использует его значение как имя каталога, в котором bash создаёт временные файлы для использования оболочкой.

auto_resume
Эта переменная управляет тем, как оболочка взаимодействует с пользователем и управлением заданиями. Если эта переменная установлена, простые команды, состоящие только из одного слова, без перенаправлений, рассматриваются как кандидаты для возобновления существующего остановленного задания. Не допускается неоднозначность; если есть более одного задания, начинающегося с или содержащего слово, выбирается последнее использованное задание. Имя остановленного задания в этом контексте — это командная строка, использованная для его запуска, как отображается командой jobs. Если установлено значение exact, слово должно точно соответствовать имени остановленного задания; если установлено substring, слово должно соответствовать подстроке имени остановленного задания. Значение substring предоставляет функциональность, аналогичную идентификатору задания %? (см. УПРАВЛЕНИЕ ЗАДАНИЯМИ ниже). Если установлено любое другое значение (например, prefix), слово должно быть префиксом имени остановленного задания; это предоставляет функциональность, аналогичную идентификатору задания %string.

histchars
Два или три символа, которые управляют расширением истории, быстрой заменой и токенизацией (см. РАСШИРЕНИЕ ИСТОРИИ ниже). Первый символ — символ расширения истории, символ, который начинает расширение истории, обычно «!». Второй символ — символ быстрой замены, обычно «^». Когда он появляется как первый символ строки, подстановка истории повторяет предыдущую команду, заменяя одну строку другой. Необязательный третий символ — символ комментария истории, обычно «#», который указывает, что остаток строки является комментарием, когда он появляется как первый символ слова. Символ комментария истории отключает расширение истории для оставшихся слов в строке. Он не обязательно заставляет парсер оболочки рассматривать остаток строки как комментарий.

Массивы

Bash предоставляет одномерные индексированные и ассоциативные массивы. Любая переменная может использоваться как индексированный массив; встроенная команда declare явно объявляет массив. Нет максимального ограничения на размер массива, и нет требования, чтобы элементы индексировались или присваивались последовательно. Индексированные массивы ссылаются с использованием арифметических выражений, которые должны раскрываться в целое число (см. АРИФМЕТИЧЕСКИЕ ВЫЧИСЛЕНИЯ ниже) и используют нумерацию с нуля; ассоциативные массивы ссылаются с использованием произвольных строк. Если не указано иное, индексы индексированных массивов должны быть неотрицательными целыми числами.

Оболочка выполняет раскрытие параметров и переменных, арифметическое раскрытие, подстановку команд и удаление кавычек на индексах индексированных массивов. Поскольку это может потенциально привести к пустым строкам, индексирование подстрочных индексов рассматривает их как выражения, которые вычисляются в 0.

Оболочка выполняет раскрытие тильды, раскрытие параметров и переменных, арифметическое раскрытие, подстановку команд и удаление кавычек на индексах ассоциативных массивов. Пустые строки не могут использоваться как ключи ассоциативных массивов.

Bash автоматически создаёт индексированный массив, если какая-либо переменная присваивается с использованием синтаксиса `name[subscript]=value` Индекс subscript рассматривается как арифметическое выражение, которое должно вычисляться в число больше или равное нулю. Чтобы явно объявить индексированный массив, используйте `declare -a name`
(см. ВСТРОЕННЫЕ КОМАНДЫ ОБОЛОЧКИ ниже). `declare -a name[subscript]`
также принимается; subscript игнорируется.

Ассоциативные массивы создаются с использованием `declare -A name`
Атрибуты могут быть указаны для переменной-массива с использованием встроенных команд declare и readonly. Каждый атрибут применяется ко всем элементам массива.

Массивы присваиваются с использованием составных присваиваний вида name=(value1 ... valuen), где каждое value может быть вида [subscript]=string. Присваивания индексированных массивов не требуют ничего, кроме string. Каждое value в списке раскрывается с использованием раскрытий оболочки, описанных ниже в разделе РАСКРЫТИЕ, но value, которые являются допустимыми присваиваниями переменных, включая скобки и индекс, не подвергаются раскрытию фигурных скобок и разбиению на слова, как и отдельные присваивания переменных.

При присваивании индексированным массивам, если указаны необязательные скобки и индекс, присваивается этот индекс; в противном случае индекс присваиваемого элемента — это последний индекс, присвоенный оператором, плюс один. Индексация начинается с нуля.

При присваивании ассоциативному массиву, слова в составном присваивании могут быть либо операторами присваивания, для которых требуется индекс, либо списком слов, который интерпретируется как последовательность чередующихся ключей и значений: name=(key1 value1 key2 value2 ...). Они обрабатываются идентично name=([key1]=value1 [key2]=value2 ...). Первое слово в списке определяет, как интерпретируются оставшиеся слова; все присваивания в списке должны быть одного типа. При использовании пар ключ/значение ключи не могут отсутствовать или быть пустыми; отсутствующее конечное значение обрабатывается как пустая строка.

Этот синтаксис также принимается встроенной командой declare. Отдельные элементы массива могут быть присвоены с использованием синтаксиса name[subscript]=value, представленного выше.

При присваивании индексированному массиву, если name индексируется отрицательным числом, это число интерпретируется относительно единицы плюс максимальный индекс name, так что отрицательные индексы отсчитываются с конца массива, и индекс -1 ссылается на последний элемент.

Оператор «+=» добавляет к переменной-массиву при присваивании с использованием синтаксиса составного присваивания; см. ПАРАМЕТРЫ выше.

Элемент массива ссылается с использованием ${name[subscript]}. Фигурные скобки требуются, чтобы избежать конфликтов с раскрытием путей. Если subscript — @ или *****, слово раскрывается во всех элементах name, если не указано иное в описании встроенной команды или раскрытия слова. Эти подстрочные индексы различаются только тогда, когда слово появляется внутри двойных кавычек. Если слово в двойных кавычках, ${name[*]} раскрывается в одно слово со значением каждого элемента массива, разделённым первым символом специальной переменной IFS, а ${name[@]} раскрывает каждый элемент name в отдельное слово. Когда нет элементов массива, ${name[@]} раскрывается в ничто. Если двойное раскрытие происходит внутри слова, раскрытие первого параметра объединяется с начальной частью раскрытия исходного слова, а раскрытие последнего параметра объединяется с конечной частью раскрытия исходного слова. Это аналогично раскрытию специальных параметров ***** и @ (см. Специальные параметры выше).

${#name[subscript]} раскрывается в длину ${name[subscript]}. Если subscript — ***** или @, раскрытие — это количество элементов в массиве.

Если индекс, используемый для ссылки на элемент индексированного массива, вычисляется в число меньше нуля, он интерпретируется относительно единицы плюс максимальный индекс массива, так что отрицательные индексы отсчитываются с конца массива, и индекс -1 ссылается на последний элемент.

Ссылка на переменную-массив без индекса эквивалентна ссылке на массив с индексом 0. Любая ссылка на переменную с использованием допустимого индекса допустима; bash создаёт массив, если необходимо.

Переменная-массив считается установленной, если индекс был присвоен значение. Пустая строка является допустимым значением.

Можно получить ключи (индексы) массива, а также значения. ${!name[@]} и ${!name[]} раскрываются в индексы, присвоенные в переменной-массиве name. Обработка в двойных кавычках аналогична раскрытию специальных параметров @ и __ внутри двойных кавычек.

Встроенная команда unset используется для уничтожения массивов. unset name[subscript] снимает элемент массива по индексу subscript для индексированных и ассоциативных массивов. Отрицательные индексы для индексированных массивов интерпретируются, как описано выше. Снятие последнего элемента переменной-массива не снимает переменную. unset name, где name — массив, удаляет весь массив. unset name[subscript] ведёт себя по-разному в зависимости от того, является ли name индексированным или ассоциативным массивом, когда subscript — ***** или @. Если name — ассоциативный массив, это снимает элемент с индексом ***** или @. Если name — индексированный массив, unset удаляет все элементы, но не удаляет сам массив.

При использовании имени переменной с индексом в качестве аргумента команды, такой как unset, без использования синтаксиса раскрытия слов, описанного выше (например, unset a[4]), аргумент подвергается раскрытию путей. Процитируйте аргумент, если раскрытие путей нежелательно (например, unset 'a[4]').

Встроенные команды declare, local и readonly каждая принимают опцию -a для указания индексированного массива и опцию -A для указания ассоциативного массива. Если обе опции указаны, -A имеет приоритет. Встроенная команда read принимает опцию -a для присваивания списка слов, прочитанных из стандартного ввода, массиву. Встроенные команды set и declare отображают значения массивов таким образом, что их можно повторно использовать в качестве присваиваний. Другие встроенные команды также принимают имена массивов в качестве аргументов (например, mapfile); см. описания отдельных встроенных команд ниже для деталей. Оболочка предоставляет ряд встроенных переменных-массивов.
